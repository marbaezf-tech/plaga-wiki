1. Ollama — Modelos Locales

Instalación

  1. Descargar de ollama.com/download
  2. Instalar (ejecutar .exe)
  3. Verificar: ollama --version

Comandos Básicos

ollama serve          # Iniciar servidor
ollama list           # Ver modelos instalados
ollama pull qwen2.5:7b  # Descargar modelo
ollama run qwen2.5:7b   # Chat interactivo
ollama ps             # Ver modelos cargados en GPU
ollama rm nombre      # Borrar modelo

Crear Modelo Personalizado (Modelfile)

FROM qwen2.5:7b

PARAMETER temperature 0.7
PARAMETER num_ctx 16384
PARAMETER num_predict 2000
PARAMETER stop "<|im_end|>"

SYSTEM """Eres un asistente experto en GDScript.
Responde en español. Da código completo."""

Crear: ollama create mi-modelo -f Modelfile.mi-modelo

Parámetros Importantes

ParámetroQué haceValor típico
temperatureCreatividad (0=exacto, 1=random)0.3 código, 0.85 narrativa
num_ctxVentana de contexto (tokens)16384 o 32768
num_predictMáx tokens a generar400-4096
num_gpuCapas en GPU (99=todas)99
repeat_penaltyPenaliza repetición1.1-1.2

Variables de Entorno

set CUDA_VISIBLE_DEVICES=0,1     # Usar ambas GPUs
set OLLAMA_NUM_GPU=99            # Todo a GPU
set OLLAMA_MAX_LOADED_MODELS=2   # 2 modelos simultáneos
set OLLAMA_FLASH_ATTENTION=1     # Menos VRAM
ollama serve

2. Fine-tuning con LoRA

Dataset (formato JSONL)

{"instruction":"¿Quién es X?","input":"","output":"X es un NPC que..."}
{"instruction":"Escribe código para Y","input":"","output":"func _ready():\n\tpass"}

Proceso

  1. Preparar dataset JSONL (100-500 ejemplos mínimo)
  2. Entrenar con LoRA: python train_qwen3.py
  3. Mergear LoRA con modelo base
  4. Convertir a GGUF: python convert_hf_to_gguf.py ./merged --outfile modelo.gguf --outtype q4_k_m
  5. Crear en Ollama: ollama create mi-modelo -f Modelfile
Tips: 3-5 épocas es suficiente. Más no siempre es mejor. Entrenar "no sé" es tan importante como entrenar datos reales.

3. MCP Server — Tu propio servidor de datos

Concepto

MCP = Model Context Protocol. El LLM llama a "herramientas" de tu server para obtener datos reales en vez de inventar.

Usuario pregunta → LLM decide usar tool → MCP Server busca datos → Devuelve resultado → LLM responde con datos reales

Ejemplo Mínimo (server.py)

from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp.types import Tool, TextContent

app = Server("mi-server")

@app.list_tools()
async def list_tools():
    return [Tool(
        name="buscar_dato",
        description="Busca un dato por nombre",
        inputSchema={"type":"object","properties":{"nombre":{"type":"string"}},"required":["nombre"]}
    )]

@app.call_tool()
async def call_tool(name, arguments):
    # Aquí tu lógica de búsqueda
    resultado = buscar_en_json(arguments["nombre"])
    return [TextContent(type="text", text=resultado)]

Instalar dependencias

pip install mcp fastapi uvicorn

4. Continue — IA en VS Code

Instalación

  1. VS Code → Extensions → buscar "Continue"
  2. Instalar "Continue - open source AI code agent"

Config: ~/.continue/config.yaml

name: Mi Config
version: 1.0.0
schema: v1
models:
  - name: Mi Modelo
    provider: ollama
    model: nombre-en-ollama
    apiBase: http://localhost:11434
    capabilities:
      - tool_use
    roles: [chat, edit, apply]

rules:
  - Regla 1 que siempre se inyecta
  - Regla 2

mcpServers:
  - name: Mi MCP
    command: python
    args: [C:\ruta\server.py]
    autoApprove: [herramienta1, herramienta2]

Atajos

AtajoAcción
Ctrl+LAbrir chat Continue
Ctrl+IEditar código con IA
Ctrl+'Cambiar modelo

Modos

ModoCuándo usar
ChatPreguntas simples, consultas
AgentTareas complejas (3+ archivos)
PlanPlanificar antes de actuar

7. Dual GPU

Problema: Si ves "42%/58% CPU/GPU" en ollama ps, el modelo no cabe completo en GPU → lento.

Solución

set CUDA_VISIBLE_DEVICES=0,1
set OLLAMA_NUM_GPU=99
set OLLAMA_FLASH_ATTENTION=1
ollama serve

Reducir contexto si no cabe: PARAMETER num_ctx 16384 (en vez de 32768)

Verificar

ollama ps          # Debe decir "100% GPU"
nvidia-smi -l 2    # Monitorear VRAM en tiempo real

8. MoE Router

Concepto

Varios modelos especializados + un clasificador que decide cuál usar:

Pregunta → Clasificador (keywords) → Modelo correcto
  código  → plaga-coder (7B)
  lore    → plaga-qwen3 (4B fine-tuned)
  narrat  → plaga-narrator (9B)

Cuándo usar MoE vs un solo modelo

EscenarioRecomendación
Dominio únicoUn modelo grande
Múltiples dominiosMoE con especializados
VRAM limitadaMoE con modelos chicos
Fine-tuning por dominioMoE obligatorio
