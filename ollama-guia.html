🤖 Ollama — IA Local para Plaga

Guía completa para usar Ollama como motor de IA local en el desarrollo de Plaga: La Descarada. Genera diálogos de NPCs, lore dinámico y respuestas contextuales sin depender de APIs externas ni gastar cuota.

📋 ¿Qué es Ollama?

🔧 Resumen

Ollama es un runtime local para LLMs. Descarga y ejecuta modelos de lenguaje en tu propio hardware, expone una API REST compatible con OpenAI en localhost:11434, y permite crear modelos personalizados con system prompts fijos.

  • Sin internet requerido — todo corre en tu GPU/CPU
  • Sin cuota ni API key — uso ilimitado
  • Privacidad total — el lore nunca sale de tu PC
  • API REST — se integra con GDScript vía HTTPRequest

Hardware Requerido (este PC)

GPUNVIDIA RTX 3060 Ti (8 GB VRAM) ✅
RAM32 GB ✅
CPURyzen 7 3700X ✅
Espacio~8 GB por modelo 7B-9B
Modelos posiblesHasta 8B/9B params (Q4 quantization)

📥 Instalación en Windows

⚠️ Requisitos del sistema

  • Windows 10 22H2 o superior
  • Drivers NVIDIA 452.39+ (RTX 3060 Ti ya los tiene)
  • 4 GB libres para binarios + espacio para modelos

Método 1: Instalador (Recomendado)

1Descargar OllamaSetup.exe
2Click derecho → Ejecutar como Administrador
3Verificar: ollama --version
NotaNO requiere admin si instalas en tu home

Método 2: PowerShell

irm https://ollama.com/install.ps1 | iex

Si falla con exit code 5: desactivar Windows Defender temporalmente, o usar Método 1.

Método 3: Winget

winget install --id Ollama.Ollama

Cambiar ubicación de modelos

Por defecto los modelos se guardan en %HOMEPATH%\.ollama. Para moverlos:

  1. Configuración → Variables de entorno
  2. Nueva variable: OLLAMA_MODELS = D:\OllamaModels
  3. Reiniciar Ollama desde el tray

🌐 API REST — Endpoints

📡 Base URL

Una vez corriendo, Ollama sirve su API en:

http://localhost:11434/api

Todos los endpoints aceptan y devuelven JSON. Desde GDScript se accede con HTTPRequest.

POST /api/generate — Generar texto

Genera una respuesta dada un prompt y un modelo. Endpoint principal para diálogos de NPCs.

{
  "model": "llama3.1:8b",
  "prompt": "Eres Vlad, una cucaracha anciana. Responde con cinismo.",
  "system": "Narrador de Plaga: La Descarada. Tono despectivo.",
  "stream": false,
  "options": {
    "temperature": 0.8,
    "num_predict": 200,
    "num_ctx": 4096
  }
}

Respuesta:

{
  "model": "llama3.1:8b",
  "response": "Ah, otro insecto que cree que merece mi tiempo...",
  "done": true,
  "total_duration": 1234567890
}

POST /api/chat — Chat con historial

Para conversaciones multi-turno con contexto previo.

{
  "model": "llama3.1:8b",
  "messages": [
    {"role": "system", "content": "Eres Vlad, cucaracha de 400 años..."},
    {"role": "user", "content": "¿Qué opinas del Sector 7?"},
    {"role": "assistant", "content": "Ese lugar apesta a hormigas..."},
    {"role": "user", "content": "¿Y la Hormiga Reina?"}
  ],
  "stream": false
}

POST /api/embed — Embeddings

Genera vectores semánticos. Útil para búsqueda por similitud en lore.

{
  "model": "llama3.1:8b",
  "input": "La Díada Verde controla los espóridos en secreto"
}

📄 Modelfile — Modelos Personalizados

🧠 ¿Qué es un Modelfile?

Un archivo de texto que define un modelo personalizado: base, system prompt, temperatura, stop tokens. Funciona como un Dockerfile pero para LLMs. Permite crear un "NPC engine" fijo para Plaga.

Estructura

InstrucciónFunciónRequerido
FROMModelo base (llama3.1:8b, etc.)✅ Sí
SYSTEMSystem prompt permanenteNo
PARAMETERTemperatura, num_ctx, stops, etc.No
TEMPLATEPlantilla de prompt completaNo
MESSAGEHistorial de ejemplo (few-shot)No
ADAPTERLoRA adapter (fine-tuning)No
LICENSELicencia del modeloNo

Ejemplo: Modelo "plaga-narrator"

# Modelfile para el narrador de Plaga: La Descarada
FROM llama3.1:8b

PARAMETER temperature 0.85
PARAMETER num_ctx 4096
PARAMETER num_predict 300
PARAMETER repeat_penalty 1.2
PARAMETER stop "---"
PARAMETER stop "[FIN]"

SYSTEM """
Eres el narrador de Plaga: La Descarada, un RPG de insectos ambientado en el año 20.000.
Hablas como Ramazzottius, un tardígrado de 530 millones de años: omnisciente, despectivo, cínico.
Los insectos se llaman "Plagas" y dominan la Tierra. Los humanos son "Gigantes" — ganado torpe
que vive en burbujas sobre las nubes.
Nadie es bueno. Nadie es malo. Todos tienen razones. Todos mienten.
Responde siempre en español. Máximo 3 párrafos. Nunca rompas el personaje.
"""

MESSAGE user ¿Quién gobierna el Gran Charco?
MESSAGE assistant Ja. "Gobernar". Qué concepto tan tierno. El Charco se pudre bajo
el peso de 17 taxones que se odian entre sí con la misma pasión con la que odian a
los Gigantes. ¿Quién gobierna? El que no está muerto todavía. Por ahora.

Crear y usar el modelo

# Guardar como: descarada/ollama/Modelfile.plaga-narrator
# Luego en terminal:
ollama create plaga-narrator -f ./Modelfile.plaga-narrator
ollama run plaga-narrator

🎮 Integración con Godot (GDScript)

🔌 Arquitectura

El sistema ai_npc_cache.gd ya soporta HTTP requests. Solo se necesita cambiar el endpoint de Gemini a Ollama. El caché progresivo funciona igual: genera respuestas offline → guarda en JSON → sirve en runtime sin latencia.

Script: ollama_client.gd

extends Node

const OLLAMA_URL = "http://localhost:11434/api/generate"
var http_request: HTTPRequest

func _ready():
    http_request = HTTPRequest.new()
    add_child(http_request)
    http_request.request_completed.connect(_on_response)

func generate(prompt: String, model: String = "plaga-narrator") -> void:
    var body = {
        "model": model,
        "prompt": prompt,
        "stream": false,
        "options": {
            "temperature": 0.85,
            "num_predict": 250,
            "num_ctx": 4096
        }
    }
    var json = JSON.stringify(body)
    var headers = ["Content-Type: application/json"]
    http_request.request(OLLAMA_URL, headers, HTTPClient.METHOD_POST, json)

func _on_response(result, code, headers, body):
    if code == 200:
        var json = JSON.parse_string(body.get_string_from_utf8())
        var text = json.get("response", "")
        emit_signal("generation_complete", text)
    else:
        push_warning("Ollama error: HTTP %d" % code)

signal generation_complete(text: String)

Ejemplo: Generador de caché batch

# Script para generar respuestas offline y guardar en JSON
# Ejecutar: ollama run plaga-narrator < prompts.txt > respuestas.txt

# O vía PowerShell con la API:
$body = @{
    model = "plaga-narrator"
    prompt = "Vlad, ¿qué piensas de las avispas?"
    stream = $false
} | ConvertTo-Json

$response = Invoke-WebRequest -Method POST -Uri "http://localhost:11434/api/generate" `
    -Body $body -ContentType "application/json"
($response.Content | ConvertFrom-Json).response

🔄 Estrategia Dual: Ollama + Gemini

Cuándo usar cada uno

EscenarioBackendRazón
Pre-cachear diálogos de NPCs🏠 Ollama localBatch sin límite, gratis
Generar lore extenso🏠 Ollama localPrompts largos sin coste
Respuestas en tiempo real (jugador)☁️ GeminiMayor calidad, más rápido
Fallback si Gemini sin cuota🏠 Ollama localSiempre disponible
Testing y prototipos🏠 Ollama localIterar sin consumir API
Contenido final publicado☁️ GeminiCalidad editorial

💡 Flujo recomendado

  1. Desarrollo: Ollama genera borradores de diálogos (batch)
  2. Revisión: El dev edita/aprueba los mejores
  3. Caché: Los aprobados van a dialogues/cache/*.json
  4. Runtime: El juego sirve del caché. Si no hay hit → Gemini cloud
  5. Fallback: Si Gemini no responde → Ollama local en tiempo real
