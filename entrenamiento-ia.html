⚠️ Requisitos

  • Python 3.10+ instalado
  • CUDA toolkit (viene con drivers NVIDIA)
  • Dataset con mínimo 50 pares (recomendado 300+)
  • ~6-8 GB de VRAM libres (cerrar juegos)

1️⃣ Instalar dependencias (una sola vez)

pip install "unsloth[colab-new] @ git+https://github.com/unslothai/unsloth.git" pip install --no-deps trl peft accelerate bitsandbytes pip install datasets transformers torch

2️⃣ Script de entrenamiento

python train_plaga.py --dataset dataset_plaga.jsonl --epochs 3 --output plaga-lora

El script train_plaga.py se genera automáticamente al exportar el dataset.

3️⃣ Importar a Ollama

📖 Guía de Fine-tuning

¿Qué es QLoRA?

QLoRA (Quantized Low-Rank Adaptation) entrena solo ~2% de los parámetros del modelo usando 4-bit quantization. Resultado: un modelo de 8B parámetros cabe en 8GB de VRAM para entrenamiento. El modelo base no cambia — solo se agregan pequeños "adaptadores" encima.

Formato del Dataset (JSONL)

{"instruction": "¿Quién es Vlad?", "input": "", "output": "Vlad es una cucaracha anciana de 400 años..."} {"instruction": "Narra la llegada al Gran Charco", "input": "", "output": "Otro insecto creyendo que el mundo..."}

Cada línea es un JSON independiente con 3 campos:

  • instruction — Lo que el usuario preguntaría
  • input — Contexto extra (opcional, puede ir vacío)
  • output — La respuesta ideal que queremos que aprenda

Consejos para pares de alta calidad

✅ Bueno❌ Malo
Respuestas con tono cínico y vocabulario del juegoRespuestas genéricas sin personalidad
Datos precisos (nombres, zonas, facciones)Información inventada o contradictoria
Variedad de preguntas sobre el mismo temaMuchos pares repetitivos
Incluir diálogos de NPCs con personalidad propiaTodos los NPCs hablando igual
Mezclar narración + datos + opinionesSolo datos secos tipo enciclopedia

Flujo de trabajo recomendado

  1. Auto-generar base desde la wiki (~150 pares)
  2. Usar el Chat IA para generar respuestas → importar las buenas al dataset
  3. Escribir manualmente 50-100 pares "gold" con el tono perfecto
  4. Exportar JSONL y verificar calidad
  5. Entrenar de noche — lanzar y dormir
  6. Probar el modelo entrenado → repetir si hace falta
